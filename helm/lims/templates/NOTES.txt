🌐 ACCESSING THE APPLICATION
============================

{{- if .Values.ingress.enabled }}
The application is accessible via Ingress:
{{- range .Values.ingress.hosts }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}
{{- else }}

To access the application, use port-forward:

  # Frontend
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "lims.fullname" . }}-frontend 8080:{{ .Values.frontend.service.port }}

  # Backend API
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "lims.fullname" . }}-backend 3001:{{ .Values.backend.service.port }}

Then access:
  - Frontend: http://localhost:8080
  - API: http://localhost:3001
{{- end }}

{{- if or (eq .Values.backend.service.type "NodePort") (eq .Values.frontend.service.type "NodePort") }}

NodePort Access:
{{- if .Values.backend.service.nodePort }}
  - Backend: http://<node-ip>:{{ .Values.backend.service.nodePort }}
{{- end }}
{{- if .Values.frontend.service.nodePort }}
  - Frontend: http://<node-ip>:{{ .Values.frontend.service.nodePort }}
{{- end }}
{{- end }}

🔧 USEFUL COMMANDS
==================

  # View logs
  kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -f

  # Restart deployment
  kubectl rollout restart deployment -n {{ .Release.Namespace }} {{ include "lims.fullname" . }}-backend
  kubectl rollout restart deployment -n {{ .Release.Namespace }} {{ include "lims.fullname" . }}-frontend

  # Scale deployment
  kubectl scale deployment -n {{ .Release.Namespace }} {{ include "lims.fullname" . }}-backend --replicas=3

  # Upgrade release
  helm upgrade {{ .Release.Name }} ./helm/lims -n {{ .Release.Namespace }} -f values-{{ .Values.global.environment }}.yaml
